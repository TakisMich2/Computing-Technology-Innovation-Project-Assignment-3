# PhishCheck

PhishCheck is a phishing URL checker developed for COS30049 by Alyssa and Takis (new group name + number in Canvas TBD).
Enter a web address and it gives you a trust score from 0 to 100, along with a plain-language explanation of anything suspicious it finds. It uses the simple (layman level) n-gram model from Assignment 2 and supports an education campaign to help Australians protect their personal information more broadly.

| Part | Folder | Technology |
|---|---|---|
| Front end | [`frontend/`](frontend/) | React 19, React Router 7, Recharts 2, Vite 8 |
| Back end | [`backend/`](backend/) | FastAPI, Pydantic 2, scikit-learn 1.9.1, Uvicorn |
| Security analysis | [`SECURITY.md`](SECURITY.md) | Threat model, defences, attack scripts and results |

## Security work for marking

The project focuses on these security requirements to fulfil the rubric requirements + advanced requirements:

| Section | Selected work | Evidence |
|---|---|---|
| 2.7 Defence 1 | Denial of service (Advanced) | `security/dos_attack.py` |
| 2.7 Defence 2 | Unsafe model loading (Basic) | `security/model_tamper.py` |
| 2.8 Advanced attack | Detection evasion | `security/evasion_eval.py` |

We also hardened misconfiguration risks and vulnerabilities, etc, which do not fall under the defences for marking but are generally good practice for secure design.

For before-and-after demonstrations, you can disable defences using
`DISABLED_DEFENCES` in `backend/.env`. Available values are `dos`, `model`,
`evasion` and `hardening`.

## How it works


The back end never fetches or resolves the submitted URL; it only analyses the
text. There is no database: history stays in the user's own browser.

## Run PhishCheck

**Tech prerequisites**

- Python 3.14 (tested w 3.14.7)
- Node.js 22.12+ (tested w 26.13)
- MacOS/Linux: activate your virtual env with `source .venv/bin/activate`, use `cp` instead of `copy`

### 1. Set up the back end

Create and activate a virtual environment, install the back-end packages, and
copy the example settings file:

```bash
cd backend
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
```

### 2. Configure the trained model

The server needs `backend/models/MODEL_FINAL.joblib` and its SHA-256 hash in
`backend/.env`. It will not load a model if the hash does not match. See
[SECURITY.md](SECURITY.md) for details.

**Use the included model (recommended).** The submission includes
`backend/models/MODEL_FINAL.joblib` (0.3 MB). Add this hash to `backend/.env`
(this is by design and is intended to be more secure, however arguably using a
hardcoded, non-rotating hash is also not highly secure):

```
MODEL_SHA256=04b478c5fd5ee801e08499f7e32ef4bee92c6ce954f5b1d69767e8436a3d26c7
```

To check the hash yourself, run `python -m scripts.hash_model` from the
`backend/` directory.

**Download the model (only if the file is missing).** If the model is hosted
separately (by design, more details in SECURITY.md!), set its `https://` link
as `MODEL_URL` in `backend/.env`, and set `MODEL_SHA256` to the hash above. Then
run `python -m scripts.download_model`. The script removes the download if its
hash doesn't match.

N.B. *Option to train model yourself removed for demo + marker's ease.*

**What the included model was trained on.** 684,806 URLs: 449,866 from the
Mendeley dataset (23% phishing) and 234,940 from PhiUSIIL (43% phishing),
cleaned exactly as in Assignment 2. The Kaggle dataset was **not** used: it
can only be downloaded with a Kaggle account. The model's settings are
unchanged from Assignment 2: TF-IDF over character 2–5-grams with a
logistic-loss SGD classifier. Accuracy isn't assessed in this assignment, so
the model is treated as a black box.

### 3. Build the front end

```bash
cd ../frontend
npm ci
npm run build
```

`npm ci` installs exactly the versions in `package-lock.json`.

### 4. Start

```bash
cd ../backend
python run.py
```

Then open **http://127.0.0.1:8000**. The back end serves both the API and the
built front end from one origin.

### Run in development mode

For a faster front-end workflow, run `python run.py` in `backend/` and
`npm run dev` in `frontend/`, then open http://localhost:5173. Vite reloads
the page when you save changes and forwards `/api` requests to the back end on
port 8000.

## API documentation

Interactive documentation is generated by FastAPI at **`/docs`**. It is turned
off by default, because exposed docs are a misconfiguration risk. You can still
view it by following the steps below:

1. Set `ENABLE_DOCS=true` in `backend/.env`.
2. Restart the server with `python run.py`, then visit **http://127.0.0.1:8000/docs**.

Each endpoint includes a description, example requests (select one from the
**Examples** list after **Try it out**) and example success and error
responses.

| Method | Path | Purpose |
|---|---|---|
| `POST` | `/api/assess` | Score one URL. Body `{"url": "..."}` (max 2,048 characters, 8 KB body). Returns the trust score, phishing probability, prediction, the URL the model analysed after normalisation, and explained warnings. |
| `GET` | `/api/health` | Whether the server is up and the model is loaded. The front end calls it on load to warn early if the back end is down. |

Every error uses one JSON shape, with no stack traces or internal details:

```json
{"error": {"code": "invalid_input", "message": "URL cannot be empty.",
           "details": [{"field": "url", "message": "URL cannot be empty."}],
           "request_id": "8e0a5c0dbdc24f41"}}
```

| Status | Code | When it occurs |
|---|---|---|
| 422 | `invalid_input` / `invalid_url` | The URL is empty, too long, contains spaces, has unknown fields, or the body isn't valid JSON |
| 413 | `payload_too_large` | The request body is over 8 KB (checked before parsing, even if `Content-Length` is missing) |
| 404 / 405 | `not_found` / `method_not_allowed` | The endpoint doesn't exist, or the wrong method was used |
| 503 | `service_busy` | The inference queue is full; the response includes `Retry-After` |
| 500 | `internal_error` | Something unexpected happened; details are logged on the server only |

## Threat model at a glance

(High-level only: covered in more detail in [SECURITY.md](SECURITY.md).)

**What we're protecting:** service availability, the integrity of phishing
verdicts (a phishing link must not be passed as safe), the server that loads
the model file, and the privacy of the addresses users check.

**Attackers:** anyone who can reach the API. 

**Entry points:** `POST /api/assess`, `GET /api/health`, the static front-end
files, and the model file on disk.

| Risk | Applies? | Response |
|---|---|---|
| Denial of service | Yes | **Defence 1.** Body and URL size limits, inference off the event loop, and a bounded queue that returns 503 when full |
| Unsafe model loading | Yes | **Defence 2.** The server checks the model's SHA-256 at startup before `joblib.load`, refuses to start on a mismatch, and unpickles only the verified bytes |
| Detection evasion (look-alike letters, invisible characters, encodings) | Yes | **Advanced attack.** Unicode normalisation before analysis; look-alike host names are capped at trust 5 |
| Misconfiguration / vulnerable dependencies | Yes | Hardened, but not selected for marking: security headers, docs disabled by default, no server banner, strict CORS, and audited pinned dependencies |
| Missing rate limiting | Yes | Partly covered by the global admission gate; per-client limits are not built |
| Command injection, SQL injection, file upload, SSRF, broken access control | No | No shell calls, no database, no uploads, the URL is never fetched, and no accounts |

The full table with reasons, measurements and costs is in [SECURITY.md](SECURITY.md).

## Configuration

All settings are in `backend/.env`; see
[`.env.example`](backend/.env.example) for the available options. There are
no deployment-specific settings or secrets in the source code, and the front
end doesn't contain secrets. The `.env` file is git-ignored and isn't included
in the submission ZIP.
